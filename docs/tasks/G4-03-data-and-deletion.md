## Scope and acceptance

Outcome: a signed-in user can open "Your data", see what the app stores and each past session's provider cleanup status, retry outstanding cleanup, and delete all their practice data with an explicit typed confirmation.
Non-goals: Auth account deletion, deleting session metadata rows (no migration in G4), ElevenLabs deletion, reflections (never stored).

- [ ] `GET /api/sessions`: `handle`, `requireIdentity()` first, owner-RLS select on `practice_sessions` with explicit columns `id,status,cleanup,created_at,ended_at`, `order created_at desc`, `limit 50`; never select `provider_conversation_id`, `request_fingerprint` or `idempotency_key`. Map and validate with `sessionListResponseSchema`; malformed → 503.
- [ ] `DELETE /api/practice-data`: `requireIdentity()` before body; `readBody(request, deletePracticeDataRequestSchema, 256)`. In `lib/data/practice-data.ts`: list the owner's people and facts (owner-RLS selects), delete each person via `person_delete` then each fact via `about_me_delete` using `rpc()` from `lib/data/rpc.ts` (treat NOT_FOUND as already deleted), then `private_prep_put('')`. Continue past individual failures, then re-read to compute `remaining` truthfully; read session counts (`total`, `cleanupConfirmed` = cleanup `confirmed`, `cleanupOutstanding` = `pending` or `unresolved`). Validate with `deletePracticeDataResponseSchema`. Never direct table DML.
- [ ] `/practice/data` page requires sign-in like `app/practice/about-me/page.tsx` (redirect to `/auth/sign-in`). Content:
  - What is stored: About-me facts, saved people and what each knows, private prep notes (counts with links to manage them), and session records (status and cleanup only; no audio, video, transcript or reflection is stored by this app).
  - Providers, stated truthfully: video calls run on Tavus; when cleanup shows "Deleted at provider", the app verified the Tavus conversation ended and requested hard deletion. Voices are generated by ElevenLabs through Tavus; this app does not track or delete ElevenLabs copies. Setup and reflection text goes to OpenAI with storage disabled for the request (`store: false`); the provider's own retention policies may still apply.
  - Past sessions list (date/time, status, cleanup label: confirmed → "Deleted at provider", pending → "Provider cleanup pending", unresolved → "Provider cleanup not confirmed", not_started → "No provider call"), with "Retry cleanup" for pending/unresolved terminal sessions that calls `POST /api/sessions/{id}/end` with `{ reason: "user" }` and refreshes the row from the response. Active sessions show "In progress" with no retry.
  - "Delete all practice data": opens an inline confirmation requiring the exact phrase `delete my practice data`, explains that session records are kept to track provider cleanup and that the account itself is not deleted; on response shows deleted counts, and if anything remains, says deletion was incomplete with a retry. Never claims instant deletion from all providers.
  - Links back to `/practice`.
