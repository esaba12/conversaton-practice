# Experience and interface

## Visual direction
Confirmed direction: warm and minimal, but crisp and modern. Warm ivory background, near-white surfaces, charcoal text, one muted sage accent, precise spacing, and clear sans-serif type. Use restrained 12-16px corners and thin borders. The practice screen is a FaceTime-style call with a large live talking AI counterpart, not an audio visualization or static portrait. Keep the surrounding controls quiet so the counterpart remains the focus. Avoid clinical dashboards, mood heatmaps, competitive streaks, and red countdown pressure. See docs/18-DESIGN-AND-AWS.md for the proposed palette and [the live video contract](22-LIVE-VIDEO.md) for media behavior.

## Screens

### Sign-in
Public entry explains the practice tool and offers sign-in/create-account. Sign-in is required before any persona design, setup generation, or practice. Return authenticated users to their own workspace.

**As built (UI landing):** `/` is the public landing when signed out: the existing headline, an illustration labeled as not a live call, the three practice steps, and what the user keeps control of. Signed-in visitors to `/` see a home whose primary action is Practice a conversation (`/practice`), with About me and Your data beside it. A new email or Google sign-in still opens `/practice` so the situation stays first. Sign-in offers Continue with Google and email/password. Google uses Supabase OAuth and returns through `/auth/callback`; enabling the Google provider and allowlisting `{origin}/auth/callback` is dashboard configuration, not an app secret. The preset cards described below are not on this home. Sign-out or detected expiry stops all session audio/video, closes provider sessions, releases the microphone and any active camera tracks, and clears transient private content before returning to sign-in; server routes independently reject unauthenticated requests. Do not show a guest workspace or guest practice CTA.

### Home
Primary action: Practice a conversation.
Secondary: My people; My preferences.
Preset cards: Ask a professor for help; Talk about a roommate issue; Say no to a request.
On the practice home those three are example actions under the situation field. Generate setup stays the primary button. Each example opens review labeled “Example setup — not generated.” Starting an example the user has not edited sends only the preset id; private notes typed on the home stay out of that request. The user can still edit the role, and an edited example starts as a reviewed role.
The primary action opens a situation input. Presets are shortcuts; the user does not need to choose a category first.
Show saved takeaways as optional context, not a performance history.

### Prepare
Inputs:
- Situation, required, max 1,000 characters.
- What do you want to say or do? optional at entry, max 200; generation suggests an editable goal if omitted. Confirm one goal during review.
- What does the other person already know? optional.
- Private preparation notes, optional, labeled Not shared with the character.
Offer manual setup if draft generation fails. Ask only for useful context; do not request diagnosis or treatment history.
Generate the fictional counterpart, scenario, and opening from the situation. Let the user review the assumptions before practice. Subsequent dialogue is live and responsive. Full written scripts are outside the current scope.

### Persona review
Editable fields: alias, role, directness, formality, talkativeness, familiarity, voice, situation constraints.
Implemented in G2 (frozen `roleContextSchema`): name, role, free-text speaking style (covers directness/formality/talkativeness), what the character knows, opening line, up to five constraints, challenge (supportive/neutral/mild pushback), pace (patient/conversational), plus the user's goal marked not shared and read-only assumptions. A one-off reviewed setup keeps the default face and voice; that review screen does not offer a face picker. Manual and example setups are labeled "not generated". The situation input is limited to 1,000 characters; "what the other person already knows" is folded into the situation text.
Use concrete categorical choices rather than pseudo-scientific personality percentages.
Show What this character knows separately from Your private preparation.
Edits apply to future sessions; an active session retains its starting version.

### Practice
The main surface is a large live video of the fictional counterpart, with persona name and a persistent fictional AI roleplay label. Show the goal unobtrusively and distinguish connecting, live, listening, speaking, and interrupted states. Mark the call live only once both remote audio and counterpart video are ready; synchronize the visible speaking behavior with the delivered audio. User interruptions stop superseded speech and its speaking animation.

Controls: mic mute/unmute, camera on/off, End practice, and optional captions. Mic mute only affects microphone input; camera off only removes self-view and stops its camera tracks. Neither is a pause or an End. End practice remains visible and usable during loading and errors.

Implementation default: camera off until explicit opt-in, with a small local self-view after permission. This default has not been separately requested by the user. Explain that the counterpart listens to speech and cannot see the user: no camera frames are transmitted, analyzed, or recorded in the MVP. Camera denial must not block the counterpart video call. Turning the camera off releases its tracks immediately; turning it back on requires a fresh acquisition.

On narrow screens, preserve the main counterpart view and readable controls, with self-view tucked into a corner without covering the face or End. Captions remain optional and collapsed.

**As built:** a Show captions control sits on the call, collapsed until opened. It lists the same in-memory finished turns already collected from Tavus `conversation.utterance` for this attempt (the reflection transcript). Closing it hides that text. The only live announcement is captions on or off; new turns are not announced. Tavus `enable_closed_captions` stays false, and recording stays off. Clearing the transcript — a new call, Back to setup, Done/Skip, sign-out, auth loss, or page hide — clears the captions. A frozen frame, canned animation, or prerecorded clip must never imply that a responsive call is continuing. An audio-only or static-portrait fallback needs an explicit fallback label and cannot establish G1 acceptance.

Offer one neutral silence prompt according to the pacing setting; do not label silence a failure.
Before Start, choose 3 minutes (the default) or 5 minutes. The same choice is on a reviewed setup, each example (roommate, professor, saying no), and a saved person. The on-call timer and automatic end use that length. The start request sends it as the existing `durationSeconds` value, 180 or 300, and no other new field.
Near the planned end, allow a short natural wrap-up; enforce the server/provider duration cap as backup.
End, sign-out, auth expiry, and terminal connection failures stop playback, disconnect provider sessions, release all microphone/camera tracks, and reject late media. Preserve only the private draft needed for an authorized fresh start; auth loss clears transient private content.

### Reflection
User may skip all reflection. A later one-moment retry, decided and not built, is specified in [docs/30](30-ONE-MOMENT-RETRY.md).
Prompt: Did you get to say what mattered?
Display one behavior supported by the session, if reliable. Example: You asked what to prioritize and clarified your question.
If transcript is incomplete, show self-reflection only.
Optional: One takeaway; One next step.
Up to two memory proposals, each with Save / Edit / Dismiss.
Final primary action: Finish for now.

**As built (G4):** after End or an interruption, an optional "Reflect (optional)" panel sits below the Save/Update offer. It has a self-reflection box (not saved), "Get a short reflection" and Skip; after a result, Skip becomes Done. The generated result shows "What you did", "Takeaway" and "Next time" only when present, and labels partial or insufficient evidence. A support exit shows only a stop message with 911/988. There are no memory proposals in G4 and nothing is saved. The transcript comes from the provider's in-call transcription, is held in memory for that attempt only, and is cleared on a new call, Back to setup, Done/Skip, sign-out, auth loss and page hide. The "Your data" page (`/practice/data`, header link) shows what is stored, each session's provider cleanup status with Retry cleanup, and "Delete all practice data" behind the typed phrase `delete my practice data`.

Users save people they practice with, shape each one with trait chips, and drag About-me chips into each person's "Knows about you" area (keyboard alternative required). Private preparation stays in a separate, never-shareable section. After End, the user can explicitly choose "Save this person" or "Update". Full screen description and acceptance: [docs/26](26-PEOPLE-AND-SHARING.md).

Each starter shows a portrait from `/api/portraits/{presetId}`, or a monogram if the portrait fails. Labels only; there is no voice preview on this control. Choosing one saves immediately and applies to the next practice with that person. The section is marked "Fictional AI." There is no upload and no cloning control. A conflict asks the user to reload. The four starter practices (Practice with Jordan, and the same for Alex, Ellis, and Sam) already use that starter's face and voice; this picker is how a saved person borrows one of those four, or stays on the default. ### Profile and persona memory
Show exact stored values, source type, last updated date, and edit/delete controls.
Delete can remove an individual approved memory through a versioned edit. If a required preference returns to a default, show the default explicitly; do not silently recreate the removed value from proposal history.
Provide delete all app practice data with explicit confirmation.
Saved settings belong to the signed-in account. Clearing browser state signs the user out; signing back into the same account restores approved saved settings. Sign-out clears transient practice content.

## Error states
- Microphone denied: instructions to enable it; allow setup without audio; do not silently switch to a fake voice demo.
- Camera denied/unavailable: explain that self-view is optional; keep the counterpart video call available, with the camera off.
- Provider unavailable: preserve draft, allow reconnect with user action.
- Connection lost or counterpart video frozen/unavailable: stop media and label the call interrupted; do not silently continue audio behind a frozen face. Offer a fresh start, or an explicitly chosen and labeled audio-only fallback. A fallback does not pass the live-video gate.
- Reflection failed: leave profile unchanged; use user-written takeaway.
- Memory conflict: show current value and ask user to review; no silent overwrite.
- Deletion incomplete: show app deleted/provider pending separately.
- Credits unavailable: state the issue; do not imply the roleplay has started.

## Accessibility
Keyboard-operable controls, labeled icons, visible focus, color-independent status, reduced motion, screen-reader status announcements, optional captions, minimum 44px interaction targets. Avoid constantly announcing every transcript token.

## Demonstration moment
Show a responsive FaceTime-style exchange with a visibly talking fictional counterpart, including an interruption and clean End. Edit the same persona from formal to casual. Start a new session with the same broad scenario. Show that voice behavior and language change without the user needing to rewrite a prompt. Approve a preference update and show it on the next setup screen.
